## 2. 全 A 实时快照（最重要）

### 2.1 `pz` 上限实测 —— 只能 100

同一 URL 只改 `pz`，其他参数完全一致（`fields=f12,f13,f14`，`fid=f12`）：

| `pz` | HTTP | `data.total` | **实际返回条数** | 明文 |
|---|---|---|---|---|
| 100 | 200 | 5927 | **100** | 4.5KB |
| 101 | 200 | 5927 | **100** | 4.5KB |
| 150 | 200 | 5927 | **100** | 4.5KB |
| 500 | 200 | 5927 | **100** | 4.5KB |
| 1000 | 200 | 5927 | **100** | 4.5KB |
| **6000** | 200 | 5927 | **100** | 4.5KB |
| 10000 | 200 | 5927 | **100** | 4.5KB |

**结论**：`pz` 被服务端硬截断到 **100**，`total` 始终是真实总数（5927）。任务书里的 `pz=6000` 单请求方案**实测不可用**，只会拿到涨幅榜前 100。

补充验证（排除是参数干扰）：
- 加 `ut=b2884a393a59ad64002292a3e90d46a5` / `ut=bd1d9ddb04089700cf9c27f6f7426281`：仍 100
- `np=0`、`wbp2u=|0|0|0|web`、`push2delay.eastmoney.com`、`1./7./82.push2.eastmoney.com`：仍 100
- 字段数从 19 减到 3：仍 100（**不是按体积截断，是按条数**）

**分页边界**：
- `pn=59` → 100 条（累计 5900）
- `pn=60` → **27 条**（5927 = 59×100 + 27）✅
- `pn=61` → `{"rc":102,"rt":1,...,"data":null}` ← **必须处理 `data === null` / `rc !== 0`**

### 2.2 两种全量抓法实测对比（5927 只，19 字段）

| 方案 | 请求数 | 并发 | 墙钟耗时 | 明文 | gzip 实传 | 唯一 secid | 状态码 |
|---|---|---|---|---|---|---|---|
| **A. `clist` 60 页** | 60 | 6 | **329ms** | 1389.8KB | ~450KB | 5927/5927 | 全 200 |
| **B. `ulist.np` 8 批×800** | 8 | 4–8 | **281–531ms** | 1385.4KB | **~415KB** | 5927/5927 | 全 200 |

- 两者数据完全一致（同一时刻 `f3` 逐只对齐，见 §7 交叉验证）。
- **B 更优**：请求数 8 vs 60，连接开销/被限频风险低一个数量级；代价是**必须先有一份代码全集**（见 §2.3）。
- A 的 `fid` 建议用 **`f12`（按代码排序）** 而非 `f3`：按 `f3` 排序时榜单在盘中持续变动，翻页会**重复/漏股**。实测 `fid=f12` 60 页得到 `uniqSecids = 5927 == total`，零重复零遗漏。

### 2.3 代码全集（universe）缓存策略

`ulist` 需要显式 secid，所以 universe 需先抓一次。实测最省写法：

```
clist?pn={1..60}&pz=100&po=1&np=1&fltt=2&invt=2&fid=f12&fs={FS}&fields=f12,f13,f14
```
- 60 页 / **248ms** / **268KB**（3 字段），返回 `f12`=代码、`f13`=市场（0=深/北，1=沪）→ `secid = f13 + "." + f12`
- **每天开盘前刷一次即可**（新股上市/退市是低频事件）。这是本方案唯一"重"的请求，摊到一天可忽略。

### 2.6 数据质量坑（实测）

1. **退市/停牌占位**：5927 条里 **355–356 条 `f2 === "-"`（字符串！）**（两次全量扫描分别得 356 / 355，扫描间隔内有个别条目状态变化），`f3/f5/f6/f62` 同为 `"-"`。样例：`920680 广道退`、`600991 广汽长丰`（2013 年已退市仍占位）、`601059 信达证券`（停牌）。
   → **真实可交易 5571–5572 只**；实现里必须 `typeof x.f2 === 'number'` 过滤。
2. **`f62`（主力净流入）覆盖不全**：5572 只里 **844 只（15.1%）恒为 0**，其中北交所 354 只中有 **226 只为 0**。
   → 北交所"主力资金"基本不可用；"主力净流入"排序需把 0 视为"无数据"而非"零流入"。
3. **`f9` 市盈率亏损为负数**：5572 只里 **1491 只（26.8%）为负**（不是 `-`，也不会缺失）。
   → "低 PE 排序"必须加 `f9 > 0`，否则亏损股会排在最前。
4. **`f10` 量比在开盘头几分钟剧烈跳动**（600000 在 09:31→09:34 之间从 3.83 → 5.28 → 4.68）。开盘 15 分钟内量比不建议用于筛选。

### 2.7 限频 / 稳定性实测（关键结论）

| 场景 | 请求 | 结果 |
|---|---|---|
| 连续 12 次 `clist`（19 字段，无间隔） | 12 | **全 200**，45–281ms，avg 78.6ms，p50 57ms |
| 3 轮 × 8 并发 `ulist`（全 A 快照，无间隔） | 24 | **全 200**；墙钟 401/297/346ms；每轮 5927 行 |
| **5 秒节奏 × 6 轮**（模拟自动刷新） | 48 | **全 200**；墙钟 343/409/414/466/456/421ms；每轮 5927 行 |
| **1 秒节奏 × 8 轮**（4 倍压力） | 64 | **全 200**；墙钟 564→299ms（反而下降） |
| `ulist` 950 个 secid（URL 8.6KB） | 1 | **502 Bad Gateway**（URL 过长，非限频） |

- **未观测到任何 429 / 502（除 URL 过长）/ 空返回 / 耗时飙升**。持续 1.6 req/s（5 秒刷新）与 8 req/s（1 秒刷新）均稳定。
- **gzip 默认开启**：800 只 19 字段明文 192KB → **实传 57KB（压缩比 3.37×）**；`clist` 单页 23.7KB → 7.5KB（3.14×）。
  → 全 A 快照每个刷新周期 **实传 ~415KB**，5 秒刷新 ≈ **83KB/s**。这是评估"能不能 5 秒刷"的真实带宽指标（不是 1.4MB）。
- **`ulist` 批量上限实测**：800 → 200；850 → 200；900 → 200（URL 8189 字符）；**950 → 502**。
  → 建议固定 **800/批**（留 12% 余量，绝不贴 8KB 边界）。
- **风险提示（未验证）**：东财未公开配额。上述结论仅代表"短时间（<15 分钟）单 IP 高频"未触发；长时间 7×24 高频、或多 IP 共享出口，被临时封 IP/降级到 `push2delay` 的可能性无法排除。建议客户端实现 429/5xx 退避（1s→2s→4s）与"降级到 15s 刷新"。

| 维度 | 东财 `push2` | 新浪 `hq.sinajs` | 腾讯 `qt.gtimg` |

## 10. 最小可行请求组合（给"全A快照 + 指标排序 + 条件筛选 + 手动刷新"）

### 10.1 请求编排

| 时机 | 请求 | 数量 | 并发 | 明文/gzip | 实测耗时 | TTL |
|---|---|---|---|---|---|---|
| **启动 / 每日 09:15** | `clist` 拉 universe（`fields=f12,f13,f14`，`fid=f12`，`pn=1..60`） | 60 | 6 | 268KB / ~85KB | 248ms | **24h**（或每日定时） |
| **每次刷新** | `ulist.np` 全 A 快照（lean 15 字段，800/批） | **8** | **4–6** | 1.14MB / **~345KB** | 280–530ms | = 刷新间隔 |
| **每次刷新** | `ulist.np` 5 大指数（`fields=f2,f3,f4,f5,f6,f12,f14,f15,f16,f17,f18`） | 1 | — | 0.9KB | ~50ms(热) | = 刷新间隔 |
| **每次刷新** | `ulist.np` 涨跌家数（`f104,f105,f106`，3 个指数 secid） | 1 | — | 0.3KB | 54ms | = 刷新间隔（可 10s） |
| **每 30–60s** | `push2ex` 涨停池 + 跌停池（`pagesize=200`） | 2 | 2 | 5.1KB | 17–93ms | **30s** |
| **手动/按需** | `trends2` 分时（`ndays=1`） | 1/只 | — | 0.6KB | ~150ms | 5–10s |
| **按需/日频** | `kline` 日 K（`klt=101&fqt=1&lmt=120`） | 1/只 | 4 | 8.9KB | ~60ms | **1 天**（收盘后刷） |
| **按需** | `kline` 分钟 K（`klt=5&fqt=1&lmt=240`） | 1/只 | 4 | ~18KB | ~60ms | 1 分钟 |

**单次刷新合计：11 个请求 / 实传 ~400KB / 墙钟 < 600ms。** 5 秒刷新 = **2.2 req/s、80KB/s** —— 实测完全无压力（§2.7 用 1s 节奏压过 8 req/s 也没问题）。

### 10.2 并发与退避建议

- **并发 4–6**（`ulist` 8 批）：实测 4 并发 281ms、8 并发 401ms —— 再高收益递减，且提高被限频风险。
- **串行拉 universe 时并发 6**（60 页 / 248ms，p50 18ms）。
- **超时**：单请求 5s；**重试**：429/5xx → 1s→2s→4s，最多 3 次；`rc=102`/`data:null` 视为"翻页到底"，不重试。
- **降级**：连续 2 轮失败 → 刷新间隔 5s 提到 15s，并在 UI 标"数据可能延迟"；再失败 → 切腾讯（同 secid 换 `sh/sz/bj` 前缀 + GBK 解码）。
- **收盘后**：15:00 之后快照 TTL 放到 5 分钟（数据不变），00:00 后清缓存。

### 10.3 缓存 TTL 一览

| 数据 | TTL | 理由 |
|---|---|---|
| 代码全集 universe | **24h** | 新股/退市低频；268KB/天可忽略 |
| 全 A 快照 | **= 刷新间隔（5s）** | 盘中唯一高频项 |
| 指数 / 涨跌家数 | 5s（家数可 10s） | 便宜但没必要更快 |
| 涨停/跌停池 | 30s | 封板/炸板是分钟级事件 |
| 分时 | 5–10s（当前股票） | 只在"详情页"按需拉 |
| 日 K（120 根） | 1 天 | 收盘后失效 |
| 分钟 K | 60s | 当前 bar 会变 |

### 10.4 拿不到 / 需降级的字段

| 需求 | 现状 | 降级方案 |
|---|---|---|

export async function fetchUniverse() {
  const pages = Array.from({ length: 60 }, (_, i) => i + 1);

  for (const pn of pages) {                       // 用 6 并发见下方 pool()

  }
  return out;                                     // 实测 5927 个，唯一无重复

/** 全 A 快照：5927 只 / 8 个请求 / 约 300–500ms / gzip 实传 ~400KB */
export async function fetchSnapshot(secids) {
  const batches = [];
  for (let i = 0; i < secids.length; i += 800) batches.push(secids.slice(i, i + 800)); // 800! 950 会 502
  const rows = [];
  await pool(batches, 4, async (b) => {

      + `&fields=${FULL}&secids=${b.join(',')}`);

    for (const r of j.data.diff) {
      if (typeof r.f2 !== 'number') continue;      // 退市/停牌: f2 === "-"  ← 必须过滤
      rows.push({
        code: r.f12, market: r.f13, name: r.f14, industry: r.f100,
        price: r.f2, pct: r.f3, chg: r.f4,

        speed: r.f22,
        mcap: r.f20, floatMcap: r.f21,
        mainIn: r.f62, mainInPct: r.f184,
      });
    }
  });
  return rows;
}

async function pool(items, conc, fn) {
  let i = 0;
  await Promise.all(Array.from({ length: Math.min(conc, items.length) }, async () => {
    while (i < items.length) { const k = i++; await fn(items[k], k); }
  }));
}

## 12. 风险与未验证项（交付前请知悉）

1. **`pz=100` 硬上限是本报告最重要的推翻性结论**。任何"一次拉全 A"的实现都会静默只拿 100 条 —— 必须在 UI/日志里断言 `rows.length === total`。
2. **`ulist` 800/批 与 URL 8KB 边界强相关**（900 OK / 950 502）。代码/参数微调就可能越界 → **固定 800，不要按"能跑通的最大值"写**。
3. **本次全部测试在 09:29–09:40（开盘后 15 分钟内）**：
   - 开盘时段负载最高，说明"高峰期也能扛"，但也意味着**收盘后/夜间行为未验证**（可能更宽松）。
   - **集合竞价（09:15–09:25）行为未测**；`f2` 在 09:25 前可能为 `-`。
   - **非交易日**（周末/节假日）行为未测；`clist` 应返回上一交易日快照，但未验证。
4. **限频结论有边界**：仅证明"单 IP、<15 分钟、≤8 req/s"未触发。长期 7×24 高频、或用户量放大后的服务端聚合流量，东财可能临时封 IP 或降级到 `push2delay`。**上线前必须做退避与降级路径**。
5. **`f62/f184`（主力资金）语义未官方确认**：仅"量级自洽 + `f184 ≈ f62/f6`"两项旁证。若产品要展示"主力净流入"，建议标注"数据来源东财，口径未公开"。
6. **`f22`（涨速）窗口未确认**：与 `f11`（5 分钟）不同值，推测 <5 分钟动量，**不要在产品文案里写"涨速=5分钟涨幅"**。
7. **`f104~f106` 口径与自建 universe 差 1.4%**（5649 vs 5571）。首页"涨跌家数"与"列表统计"可能对不上，需选一套并全站统一。
8. **`f9` 亏损股为负数**（1491/5572，26.8%）、**`f62` 有 15.1% 恒为 0** —— 排序/筛选必须显式处理，否则"低估值榜"和"主力流入榜"首位会是脏数据。
9. **北交所 `0.8xxxxx` 已全部失效**，但**仍混在 `fs` 列表里**（占 355 条 `-` 中的一部分）。若产品要展示北交所，必须走 `0.920xxx`。
10. **未覆盖**：龙虎榜、资金流向明细（`f62` 以外）、财务报表、除权除息日历、板块成分股 API、盘口五档（`stock/get` 的 `f19`–`f39`）、Level-2。
