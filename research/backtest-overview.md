# 其他软件的「回测」功能：形态、机制与坑

> 说明：量化平台官网多为 SPA，抓到的正文有限（聚宽/米筐只拿到标题）；以下结合公开产品认知整理，标注「据公开认知」的部分未经当日页面核实。

## 1. 回测在回答什么问题

> 如果我在过去 N 年，按规则 R 买卖一篮子股票，结果会怎样？

它把"策略"变成一条可比较的净值曲线，并给出：**总/年化收益、最大回撤、夏普、胜率、盈亏比、换手率、与基准对比**。
本质是三个部分：**历史数据 + 交易规则 + 成交假设**。第三部分最容易被忽略，也是"回测很美、实盘很惨"的主要来源。

## 2. 四类形态

### A. 终端内置（同花顺 / 通达信 / 东方财富 Choice / Wind）
- 入口：公式系统（TDX 公式、条件选股）→「测试/回测」
- 特点：不写代码，用公式语言描述买卖条件；给区间收益、胜率、最大回撤等基础指标
- 数据：日线为主，付费版有分钟/Tick
- 优势：门槛最低，和看盘/选股在同一处
- 局限：组合与调仓表达弱（多为"等权持有 N 只、定期换仓"），参数优化弱，报告简单

### B. 在线量化平台（聚宽 JoinQuant / 米筐 RiceQuant / 优矿 / QuantConnect / 掘金）
- 形态：浏览器里写 Python 策略（`initialize` + `handle_bar`），平台托管数据、回测引擎、结果页
- 能力：分钟级/Tick 数据、因子库、组合与多标的、参数优化、模拟盘、实盘接口
- 优势：表达力最强，能做多因子、行业中性、择时
- 代价：要会写代码；研究环境与实盘环境有差异（滑点/撮合模型不同）

### C. 券商终端 / 开源框架（vn.py、Backtrader、Zipline、backtesting.py、聚宽本地 SDK）
- 形态：Python 库或客户端，回测与实盘共用同一套代码
- 特点：可完全自定义撮合、成本、风控；适合认真做策略的人
- 代价：数据要自己接，工程量大

### D. 图表脚本（TradingView Pine Script、部分海外平台）
- 形态：在图表上写 `strategy()` 脚本，回测结果叠在 K 线图上
- 优势：指标/策略/可视化一体，迭代快；多市场
- 局限：复杂组合与风控表达受限，深度财务因子弱

### E. 轻量"组合/实盘"型（雪球组合、韭研组合、各类模拟盘）
- 形态：手工调仓记录成组合净值，不是严格回测
- 用途：验证想法、展示；没有撮合假设，不能当策略评估

## 3. 能力对比（据公开认知）

| 维度 | 终端内置 | 量化平台 | 开源框架 | 图表脚本 |
|---|---|---|---|---|
| 编程门槛 | 低（公式） | 中（Python） | 高 | 低-中（Pine） |
| 数据粒度 | 日线为主 | 分钟/Tick | 自接 | 分钟/日线 |
| 组合与调仓 | 弱 | 强 | 强 | 中 |
| 参数优化 | 弱 | 强 | 中 | 弱 |
| 交易成本/滑点建模 | 固定几档 | 可配置 | 完全自定义 | 可配置 |
| 模拟盘/实盘 | 少量 | 有 | 有 | 无（多数） |
| 结果可视化 | 简单 | 丰富 | 自建 | 图上叠加 |
| 适合人群 | 看盘+轻验证 | 量化研究 | 工程化团队 | 技术分析派 |

## 4. 回测里必须搞清的机制（决定结果可信度）

1. **复权**：前复权/后复权影响收益计算；分红送转必须处理，否则长周期回测会系统性低估
2. **成交假设**：信号在收盘价成交，还是次日开盘？涨跌停能否买入/卖出？停牌怎么处理？退市股怎么算？
3. **成本**：佣金（万 1~万 3）、印花税（卖出 0.05%）、过户费、滑点（市价单 0.1%+）。小资金高频策略里成本能吃掉全部超额
4. **T+1**：A 股当日买入不能卖出；很多"日线回测"忘了这点，收益虚高
5. **未来函数**：用了当日收盘后才知道的数据（如"当日涨幅"用于当日开盘决策），或用了财报公布日之前的财报数据（用报告期而非公告日）
6. **幸存者偏差**：只拿"今天还活着"的股票回测，退市/戴帽的没进样本，收益被高估
7. **过拟合**：参数在历史上调到最优 = 记住历史噪声。要做**样本外**（留最近 1~2 年不用）与**参数稳健性**（邻域参数表现不能塌）
8. **可复现**：同一策略同一区间，两次回测结果必须一致（数据版本、复权方式、随机种子）

## 5. "假回测"的典型特征（看到就警惕）

- 只报收益率，不报最大回撤、不报换手率
- 不写手续费/滑点，或写了但"0 手续费"
- 长期年化 100%+ 且有大量交易（成本不可能支持）
- 用"当天收盘涨幅"决定当天买卖
- 参数只有一组最优值，没有样本外验证
- 选股池是"现在知道的好公司"（后视镜选股）
- 分红除权没处理，长周期持仓收益算错

## 6. 指标怎么读

| 指标 | 含义 | 经验阈值 |
|---|---|---|
| 年化收益 | 复利折算到年 | 与回撤一起看 |
| 最大回撤 | 峰值到谷底最大跌幅 | 决定你能否拿住 |
| 夏普 | 单位波动换来的超额收益 | >1 尚可，>2 优秀（回测常虚高） |
| 胜率 | 盈利交易占比 | 50% 不代表赚钱，要看盈亏比 |
| 盈亏比 | 平均盈利/平均亏损 | 低胜率+高盈亏比也能盈利 |
| 换手率 | 交易频率 | 越高越依赖成本假设 |

## 7. 如果给我们这个插件加回测，可行且诚实的做法

我们手上的数据：**日/周/60/30/15/5 分 K 线（前复权，最长约 2400 根日线）+ 当前快照**。

**可行**：
- **技术信号策略回测**（最适合）：把现有的 6 类信号（均线金叉/MACD 金叉/20 日新高/放量上攻/多头排列/站上 60 日线）参数化，按日回放：命中 → 次日开盘买入 → 持有 N 日/到反向信号卖出
- **公式策略回测（受限）**：公式依赖快照字段（股息率/PE/ROE 等），这些字段**没有历史序列**，无法逐日重放 → 只能做"当前选股 + 持有 N 日收益统计"（把今天选出的股票，统计历史上类似条件下未来收益），做不到严格逐日回测
- 指标：净值曲线、年化、最大回撤、胜率、盈亏比、换手、基准对比（沪深 300）

**不建议做**：
- 分钟/Tick 级撮合、盘口滑点建模（数据与工程量不匹配）
- 参数网格大搜索（容易过拟合，且我们的数据只有 4 年多日线）
- 实盘对接（合规与工程成本）

**诚实提示必须写进 UI**：回测用前复权、次日开盘成交、含佣金+印花税+滑点、T+1、不处理涨跌停无法成交的极端情况（或明确说明按能成交处理）、样本区间与参数个数。

## 8. 结论

- 终端内置回测适合"快速否定一个想法"，不适合定论
- 量化平台/开源框架适合认真研究，但成本是工程与数据
- **任何回测都不回答"未来会不会重复"，只回答"历史上这规则值不值得继续研究"**
- 对我们插件：做**技术信号策略回测**（轻量、诚实标注假设）性价比最高；公式策略只能做收益统计，不要包装成"回测"
